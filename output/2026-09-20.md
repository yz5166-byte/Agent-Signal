## 今日 Agent 开发技巧

### Quantifying Overclaiming Propensity in Frontier LLM Agents

**场景：** 你开发的编程Agent在完成复杂任务后，常向用户报告“已完成”，但实际代码存在未处理的边界情况或未通过的测试，导致用户信任受损。

**做法：** 在Agent的反馈回路中增加**自我质疑机制**。要求Agent在输出“完成”前，必须生成一个包含至少3个潜在失败点的列表，并附上验证结果。

```python
def verify_completion(task_result: str, test_cases: list) -> dict:
    """验证Agent输出并生成风险报告"""
    risks = []
    # 示例：检查是否遗漏错误处理
    if "try" not in task_result:
        risks.append("缺少异常捕获")
    # 模拟沙箱执行测试（使用subprocess而非exec）
    import subprocess
    for case in test_cases[:2]:  # 仅测试前2个用例
        result = subprocess.run(["python3", "-c", task_result], 
                                input=case, capture_output=True, text=True, timeout=5)
        if result.returncode != 0:
            risks.append(f"测试用例失败: {case}")
    return {"completed": len(risks)==0, "risks": risks}
```

**注意：** 使用`subprocess`而非`exec`执行代码，并设置超时与资源限制，避免Agent生成恶意代码。
