## 今日 Agent 开发技巧

### Agensh: Scaling Organizational Intelligence to 1,024 Agents

在构建多智能体系统时，若使用中心化编排器（如条目[0]所述），1024个Agent的通信会迅速耗尽上下文窗口。

做法：采用**去中心化消息总线**替代中心化编排。每个Agent只向总线发布结构化事件，其他Agent按需订阅。

```python
# 使用Redis Pub/Sub实现轻量级消息总线
import redis

bus = redis.Redis()

# Agent A发布事件
bus.publish('agent:task:done', '{"agent_id":"A","result":"..."}')

# Agent B订阅
pubsub = bus.pubsub()
pubsub.subscribe('agent:task:done')
for msg in pubsub.listen():
    print(msg['data'])
```

此模式避免单点瓶颈，支持水平扩展。注意：生产环境需对消息内容做JSON Schema校验，防止恶意数据注入。

*延伸阅读：[Agensh: Scaling Organizational Intelligence to 1,024 Agents](https://arxiv.org/abs/2609.26781v1)*
