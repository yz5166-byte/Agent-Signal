## 今日 Agent 开发技巧

### How Much Do Coding Agents Over-Edit, and Why? An Empirical Study of Unneeded Edits in Repository-Level Agent Patches

当你的代码 Agent 在仓库级任务中频繁修改无关文件（如条目[0]所述），导致审查成本飙升时，可以用 **Git 差异白名单** 约束修改范围。

做法：在 Agent 执行前注入 `allowed_paths` 列表，只允许修改指定文件。

```python
import subprocess

def safe_edit(file_path, new_content):
    allowed = ["src/", "tests/"]  # 白名单路径
    if not any(file_path.startswith(p) for p in allowed):
        raise PermissionError(f"禁止修改 {file_path}")
    # 写入前先 diff 预览
    subprocess.run(["git", "diff", "--stat", "--", file_path])
    with open(file_path, "w") as f:
        f.write(new_content)
```

这样既避免裸 `exec`，又通过文件路径白名单和 Git 预览双重防护。

*延伸阅读：[How Much Do Coding Agents Over-Edit, and Why? An Empirical Study of Unneeded Edits in Repository-Level Agent Patches](https://arxiv.org/abs/2611.34875v1)*
